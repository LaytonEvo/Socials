# A higher-fidelity keyframe — 2026-10-01

Asked for after the owner's verdict: *"It's her but almost a more AI version of her."*

## A higher-fidelity image model is not available to us

The LoRA is a **FLUX.1 [dev]** LoRA, so inference must stay on that architecture, and
ADR 0010 binds it to fal (their commercial licence covers work trained *and* run there).
Checked against the live schemas:

| endpoint | LoRAs | note |
|---|---|---|
| `fal-ai/flux-2-pro` | **no** | accepts no LoRAs; a FLUX.2 model could not load a FLUX.1 one regardless |
| `fal-ai/flux-general` | yes | same FLUX.1 [dev] base, $0.075/MP against $0.035 — control extensions, not fidelity |
| `fal-ai/flux-lora` | yes | what we use |

So swapping the image model means **retraining the LoRA**, which re-opens D-C before
anything can publish. A fidelity pass *after* generation was tested instead.

## What a detail pass does

`fal-ai/clarity-upscaler`, $0.03/megapixel (read 2026-10-01), at `creativity: 0.1` and
`resemblance: 0.9` — far below its 0.35/0.6 defaults, because invented detail on a face is
a different face.

Texture is Laplacian variance inside the detected face box, each crop resized to a constant
256×256, **and the image downsampled to 768 wide first** — which is what turbo renders
from. Measuring at generation size would repeat the confound caught in ADR 0014, where
texture correlated with face pixel size at +0.872.

| | identity | texture (face 224px) |
|---|---|---|
| keyframe, flux+LoRA | 0.97028 | 100.2 |
| **after the detail pass** | **0.96862** | **204.2** |
| her real training stills | — | 222.7 |

**Identity −0.00165, detail ×2.04.** From 45% of her real stills to 92%, and still a single
clean face — the pass invents no extra ones.

## It survives the video step

Two takes from each version of the *same* keyframe, so nothing else differs:

| source keyframe | identity min | identity mean | video texture |
|---|---|---|---|
| detailed | 0.93331 / 0.94063 | 0.95251 / 0.95331 | **203.4 / 312.3** |
| undetailed | 0.92259 / 0.94364 | 0.95178 / 0.95678 | 154.2 / 176.1 |

About **1.6× the fine detail in the finished clip**, with identity statistically unchanged
in both directions.

## The two problems are orthogonal

- **"More AI" is a fidelity problem, and the detail pass fixes it.** Identity is untouched.
- **The identity margin is a separate problem, and the detail pass does not help.** Every
  take still has 4–5 frames below 0.951, and the detailed keyframe at 0.96862 is still
  below the 0.978 keyframe bar derived in ADR 0014.

Conflating them is what sent me to `lora_scale` first, which turned out to be best at 1.3
on *both* axes.

## Blocking, and not by accident

**The licence is not cleared.** clarity-upscaler is built on Stable Diffusion 1.5 plus a
ControlNet tile and an ESRGAN upscaler, whose licences differ from each other and from
FLUX's. Nothing is pulled locally — this is a hosted call — but output licensing for
commercial use is unresolved. The slot is marked **measurement only** in
`config/providers.yaml`, the same posture as D-C: it does not block measuring, it blocks
publishing.

So this is now the **second** unresolved licence on the critical path. Both want the same
conversation with counsel.
